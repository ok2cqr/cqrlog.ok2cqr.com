What is CQRLOG

CQRLOG is a free, open-source logging program for radio amateurs, meant for everyday HF logging of CW and SSB contacts. While you work a station, it fills in what it knows: country, zones, previous contacts, QSL status and callbook data.

  • Rig and rotator control through hamlib
  • DX cluster, RBN and graphical band maps
  • LoTW, eQSL, ClubLog, HamQTH and HRDLog
  • DXCC, WAZ, ITU and IOTA statistics
  • MariaDB/MySQL database, ADIF import and export

Features

The station, not the computer

Type the callsign and CQRLOG shows the country, CQ and ITU zones, beam heading, your previous contacts with the station and whether it is a new country, band or mode for you. Name, QTH and locator come from HamQTH, QRZ.com or QRZCQ. Super Check Partial suggests calls while you type, and the whole QSO can be logged from the keyboard.

Country resolution you can rely on

DXCC, zones and IOTA are resolved with the country tables maintained by OK1RR, including dated exceptions for individual calls and expeditions. The tables update from inside the program, so old contacts keep the country that was valid at the time.

Radio, rotator and keyer

Frequency and mode are taken from the radio through hamlib, and clicking a spot tunes the radio. The rotator control gets the beam heading of the station you are working. CW goes out from memory keys through WinKeyer, K3NG, cwdaemon or hamlib, and the voice keyer plays recorded messages for SSB.

See who is on the band

DX cluster and the Reverse Beacon Network feed graphical band maps: as many windows as you like, each following the VFO or fixed on a band, with its own filter. Stations you still need stand out, and club membership can be shown next to the call. The grayline map shows where the spots come from.

Digital modes

In remote mode, contacts made in WSJT-X or fldigi are logged automatically, with the same country and QSL information as any other QSO. The WSJT-X monitor highlights CQ calls from stations you have not worked yet.

QSL without the paperwork

LoTW export is signed and uploaded in one step, and confirmations are downloaded back into the log. eQSL works both ways too. ClubLog, HamQTH and HRDLog can receive every QSO right after you save it. For paper QSLs there is a QSL manager database and label export.

Awards and statistics

DXCC, WAZ, ITU, IOTA, worked grids, big squares, DOK and US counties, by band and mode, worked and confirmed. Club membership statistics cover more than a hundred clubs, from FOC to EPC.

Your data stays yours

The log is a MariaDB/MySQL database. CQRLOG can run its own database server in your home directory, or use a server on your network so several computers share one log. Keep as many separate logs as you need, import and export ADIF, export Cabrillo, EDI and SOTA, and let CQRLOG back up the log every time you close it.

FAQ

Is this the same program as cqrlog.com?

No. This is the original CQRLOG by Petr Hlozek, OK2CQR. cqrlog.com is now used by CQRLOGImproved by Saku, OH1KH, a separate fork with its own releases and support. It's better when you mostly use digital modes.

Which package should I use on Linux?

On Ubuntu 26.04+ and Fedora 44 use the native package. On other distributions use Flatpak or Snap. The AppImage is a Qt5 build for older distributions and includes hamlib and MariaDB.

How do I install the Flatpak or the Snap?

Both are files from the release, not from an app store. Flatpak: flatpak install --user cqrlog.flatpak; when you update, add --reinstall, otherwise the old version stays installed. Snap: sudo snap install --dangerous cqrlog_*.snap, then sudo snap connect cqrlog:raw-usb for a serial rig.

Neither of them starts its own database server. Install MariaDB on the computer or use one on your network, and untick “Save log data to local machine” in the database connection window.

What do I need on macOS?

A Mac with Apple Silicon and a MariaDB server, for example from Homebrew: brew install mariadb and brew services start mariadb. hamlib and the other libraries are inside the app.

CQRLOG says that MySQL could not be started

With “Save log data to local machine” CQRLOG runs its own MariaDB server with the data in ~/.config/cqrlog/database. The server program must be installed (mariadb-server on Linux, brew install mariadb on macOS), but the system database service does not have to run.

The reason is in ~/.config/cqrlog/database/mysql.err; the error window has a button that opens it. Often it is a database server left running after CQRLOG crashed, which ends with a restart of the computer, or “Permission denied” from AppArmor on Ubuntu, which the CQRLOG .deb package sets up. If that does not help, open a GitHub issue and attach the last 20 lines of mysql.err.

Will an upgrade keep my log?

Yes. The database is upgraded on the first start of a new version; on a large log some upgrades take a while. Turn on the automatic backup in Preferences → Exit / Auto backup, so a copy of the log is saved every time you close CQRLOG.

Can several computers use one log?

Yes. Run MariaDB on one machine in your network and connect to it from each computer. CQRLOG reconnects by itself when the network or the server comes back after an outage.

How do I move my log from another program?

Export it as ADIF and import it in the QSO list window with File → Import → ADIF. Country, zones and statistics are computed during the import.

Does it work with FT8 and other digital modes?

Yes, through WSJT-X and fldigi. Turn on the remote mode in the New QSO window and the contacts you make there are logged automatically.

Where is the documentation?

The built-in help covers setup, the database, radio control and every window. Open it from Help in the menu.
